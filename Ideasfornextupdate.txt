## 🗂️ Layout & Structure

**Split the toolbar into two rows.** Right now Sort, Genre, Theme, View Toggle, and Stats are all crammed into `HDR_H` with 20px gaps between them. At narrow widths this collapses badly. Split into: a top row with the Search bar + Theme + Stats, and a bottom row with Sort + Genre filter + View toggle. This alone makes the header feel breathable.

**Left sidebar instead of tab bar.** You have 8 tabs (`N_TABS = 8`) rendering as `(win_w - 8 - 7×2) / 8`, which at the 700px minimum width gives only ~85px per tab — barely enough for "Favourites". A fixed 160px left sidebar listing All / Wishlist / Playing / Finished / etc. with a live game count badge per category would be far more scalable and look like a proper desktop app. The main content area would gain full width.

---

## 🎨 Visual Consistency

**Unify button variants to exactly two shapes.** Currently you have 5+ different button sizes: sort pill (68px), genre btn (52px), theme btn (42px), view buttons (32px), notes btn, status badge (96px). Define just two variants — icon-only (32×26) and icon+label (variable, min 52px) — both sharing the same border radius, border color logic, and hover tint. Everything becomes predictable.

**Disciplined border-radius use.** Your R_SM/R_MD/R_LG system is good but inconsistently applied. Proposal: interactive buttons → `R_SM (5)`, cards and panels → `R_LG (10)`, status badges and search bar → fully rounded (`height/2`). Tabs specifically should use `R_MD` only on the top two corners (flat bottom), which is the conventional tab shape.

**Status color left-border on list rows.** Each status has a distinct accent color visible in the badge popup, but list rows just alternate ROWA/ROWB — the status is only readable by looking at the small badge on the far right. Add a 3px vertical bar on the left edge of each row in the status accent color. At a glance you'd immediately see "this block of purple is Wishlist, this block of green is Playing." This is the pattern Letterboxd and Backloggd use.

**Column header strip.** `COL_HDR_H = 22` is too thin and visually merges with the tabs above it. Bump to 28px, uppercase the labels at f12 with slightly increased letter-spacing, and add a 1px separator below. This makes it read clearly as a table header rather than a floating label.

## 🃏 Grid View

**Taller cards with a cover placeholder zone.** `GRID_H = 158` is tight. Increase to ~195px and reserve the top ~80px as a "cover art" zone — fill it with a solid color derived from the genre (each genre gets a unique palette color) plus a centered genre icon character. This transforms the grid from a text list with columns into something that actually feels like a games library.

**One status badge per card, not 7 tiny buttons.** The grid currently shows 7 inline `GBSZ = 22` buttons per card. This is visually noisy. Use a single status badge pill at the card's bottom-right corner (matching the list view badge) that opens the same popup on click. Consistent behavior across both views, and much cleaner cards.

---

## 🔍 Search & Filtering

**Inline keyboard shortcut hint.** When the search bar is unfocused and empty, render `Ctrl+F` in a faint pill on the right side of the search box. You already support this shortcut — surfacing it is a QoL improvement.

**"Clear all" button on the chip band.** The `chip_band` only appears when genre/year filters are active. Add an `✕ Clear` button at the right end of the chip row. Currently the only way to clear all filters is pressing Escape, which isn't discoverable.

**Year range instead of single year.** `filt_year` is a single integer. A "before/after year" pair (e.g., Released: 2015–2023) would be far more useful for browsing. Even just two text inputs in the genre dropdown panel would be a big upgrade.

---

## 📊 Empty States & Stats

**Empty state screens per tab.** When a status tab has 0 games, show a centered icon (e.g., ★ for Favourites, 🎮 for All) with a short prompt: *"Nothing here yet — add a game with the + button."* Right now an empty tab likely just shows a blank list area, which feels broken.

**Visual stats panel.** The stats button exists but if the panel is just text counts, consider rendering the status distribution as a simple horizontal stacked bar using SDL filled rects — each segment in its status accent color, proportional to count. Much more compelling than "Wishlist: 12, Playing: 3…"

---

## 🌞 Light Theme

**Add at least one light theme.** All 9 current themes are dark. A "Paper" or "Daylight" theme with a warm off-white background (~`{238,234,226}`), near-black text, and a warm accent would cover accessibility concerns and round out the theme picker. The theme system is already fully in place — it's just a matter of adding a new entry to `THEMES[]` in `themes.c`.

---

The highest-impact, lowest-effort changes in order would be: **status color left-border on rows → unified button variants → empty state screens → column header height → search keyboard hint**. The sidebar navigation and grid card redesign are bigger but would make the biggest visual leap.
